# Flow naming

How the 63 entries in `scripts/test-runner/flow-catalog.json` get the names shown
in the runner. Applied, not proposed.

## The scheme

Standard QA vocabulary, lowercase, terse, one shape:

| Tier           | Shape                     | Example                             |
| -------------- | ------------------------- | ----------------------------------- |
| Curated group  | hand-written              | `sanity:smoke`                      |
| Spec file      | `<area>:<file>`           | `app:react-orders`                  |
| Describe block | `<area>:<file> > <block>` | `app:react-orders > tanstack-query` |

The ten curated groups are written by hand in
`scripts/test-runner/flow-groups.json`:

```
sanity:smoke                  contract:api
sanity:all                    ui:react
regression:full               scenarios:agents
functional:positive+negative  nonfunctional:perf+a11y
visual:snapshots              unit:components
```

The other 53 are generated by `scripts/test-runner/discover-flows.js`. Read the
functions there for the exact behaviour rather than trusting a line number here.

## Rules the generator applies

- **Area** is the folder under `tests/e2e`, lowercased. Three are renamed so the
  generated tier speaks the same words as the hand-written tier: `contracts` →
  `contract`, `non-functional` → `nonfunctional`, and a spec at the root of
  `tests/e2e` → `e2e`. A `playwright-visual` spec takes `visual` from its runner,
  having no folder to borrow.
- **File** is the spec basename, hyphens kept, minus any segment that merely
  repeats the area or its folder — `functional/negative/functional-negative`
  becomes `functional:negative`, not `functional:negative-functional-negative`.
- **When the collapse empties the file half entirely** — `tests/visual/visual.spec.ts`,
  where file, folder and area are all the word "visual" — it borrows the file's
  sole describe title instead.
- **Block** is the describe title, lowercased, stripped of small words and of
  anything already visible in the area or file half, cut to its two leading
  distinguishing segments. Where the title only restates its file, it reads
  `> all` rather than stuttering: `scenarios:rbac > all`.
- **Length budget** is about 44 characters, because these render in a table cell
  roughly 40 characters wide. Truncation happens at segment boundaries, and the
  block half is cut before the area half — the area is what a person scans by.
- **Acronyms stay lowercase.** `api`, `ui`, `rbac`, `a11y`. The whole scheme is
  lowercase and consistency beats typographic correctness here.

Descriptions are a single tooltip fragment — what runs, plus a rough cost. They
are never rendered inline; the flow list is a dense table and the description
reaches the reader through a `title` attribute.

## Ids are a contract

Flow **ids** — `group-sanity`, `spec-app-react-orders` — are untouched by any of
this and must stay that way. They appear in `.github/workflows/`, in
`docs/remote-test-runner.md`, in bookmarks, and in the `flow` input people type
into the Actions form. Only the display name and description change.

`npm run flows:check` fails if the committed catalog disagrees with what the
generator produces, so a rename that forgets to regenerate is caught in CI.

## History, so it is not repeated

An earlier pass replaced this vocabulary with prose: `sanity:smoke` became
"Quick check: home, orders, product", `regression:full` became "Everything: all
browser tests". The reasoning was that "smoke", "sanity" and "regression" are
jargon a newcomer cannot parse.

The person using the tool rejected it outright — "I need simple, smoke, sanity
sanity:smoke dont give me bullshit names i need real tests names".

They were right. Those words are the vocabulary of the trade, not jargon to be
translated away, and the audience for this runner is QA engineers. The prose
apparatus that produced the friendly names — a hand-written per-spec wording
table and eleven transformation rules — was deleted, 772 lines replaced by 351.

Do not translate them back.
