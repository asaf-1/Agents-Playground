## v1.24.0 — 2026-10-26 — the test runner, reworked

The test runner, the app colleagues use to run the suite on the pipeline without any GitHub access, is easier to pick from and can now be watched. Pick a suite, a page of the site or a single block of tests in plain words, answer one question, and follow the run on its own page until it names the tests that failed and why. It still starts the same real workflow with the same token kept on its server; nothing about who can run what has changed.

### Added

- **Three levels of picking** in `test-runner/`: suites, pages (one spec file) and single checks (one describe block), each with a sentence on what it checks, its test count, a time estimate and how it went last time, plus a search. The sentence for a page is read by `scripts/test-runner/discover-flows.js` from the comment at the top of its spec; suites carry a plain `label` in `flow-groups.json`.
- **A confirm question before Run**: what runs, where, in which browser, on how many machines, and about how long.
- **A page for each run**: Plan, the tests and Report as they happen; the failing tests with their assertions, read from the run's `remote-test-results` artifact through the new `GET /api/runs/:id/results`; the files the run left; the console output one job at a time; Cancel and Run again.
- **A fake GitHub for the runner's own tests**: `TR_GITHUB_STUB=1` swaps GitHub for `test-runner/src/github-stub.js`, so the 22 browser tests in `tests/runner/` (`npm run test:runner`) never start a real pipeline. Off unless set, never set on Render, and the header says "Stub" when it is on.
- **README pictures and GIFs**: a "See it" section, made by `npm run media:record` (`scripts/media/record.js` with Playwright, `make-gifs.py` with Pillow), with 1600px PNGs in `docs/assets/` for slides.

### Changed

- **The runner wears Playground Bank's look**: its fonts (served from `test-runner/public/fonts/`), its violet and cyan, an icon per suite and per area of the site, light and dark, and a layout that works at phone width.
- **History** gains a search by flow or person, and its outcome filter now works (it compared GitHub's conclusions with the outcome names, so most choices matched nothing).

## v1.22.0 — 2026-10-26 — the security pack and scheduled payments

Two phases of the improvement plan in one release. The security pack puts the
headers a bank would send on every response and takes the OWASP ZAP baseline
scan from 2 Medium and 5 Low findings to none, holds an email after five wrong
passwords, and adds a Devices page. Scheduled payments pay a bill on a date,
once or on a repeat, on a clock each customer can move forward so a payment due
tomorrow can be watched happening now. Deliberately not in this version: no
holidays in the weekend rule, no retry of a skipped payment, and no background
job, because due payments run when the customer shows up.

### Added

- **Security headers on every response**, from one module,
  `security-headers.js`: a Content Security Policy with a fresh nonce per view
  of `/app` and startup hashes for the classic pages' inline scripts, no
  framing, no MIME sniffing, a referrer policy, a permissions policy, the three
  cross-origin isolation headers, and HSTS behind https. Hashed assets under
  `/app/assets/` are cached for a year. A browser walk through every page in
  `react-bank-devices.spec.ts` fails on any policy refusal.
- **A hold on failed log-ins.** Five wrong passwords for one email from one
  client answer `429 TOO_MANY_ATTEMPTS` with `Retry-After`, and the hold lifts
  by itself. `BANK_LOGIN_MAX_FAILURES` and `BANK_LOGIN_HOLD_SECONDS` are
  settings, stated in `k8s/10-configmap.yaml`.
- **The Devices page** at `/app/devices`: every browser signed in to the
  account, End per device, "Log out everywhere else". New endpoints
  `GET /api/bank/sessions`, `POST /api/bank/sessions/end-others`,
  `DELETE /api/bank/sessions/{id}`.
- **Scheduled payments** on the Bill pay page: a payee, an amount, a first date
  and a repeat (once, weekly, monthly). A weekend date runs on the Monday
  after; a monthly 31st lands on the last day of a shorter month and comes
  back. A payment the account cannot cover is skipped and the customer is told.
  Endpoints under `/api/bank/scheduled-payments`.
- **A clock of your own** on the Practice page: your today is the real date
  plus the days you moved it, forward only, with a reset. Demo accounts stay on
  the real date. `GET /api/bank/clock`, `POST /api/bank/clock/advance`,
  `POST /api/bank/clock/reset`.
- **Two planted faults**, 28 and 29: `bankEndOthersKeepsOne` ("log out
  everywhere else" leaves the newest other device signed in) and
  `bankMonthlyRepeatOverflow` (a monthly 31st skips February).

### Changed

- **Terraform Validate** now runs the `terraform-github/` checks on every PR
  that touches a Terraform folder, after a manual run measured them at about 4
  seconds.
- Migrations are at 9 (`008_security.sql`, `009_scheduled.sql`). The suite is
  415 tests. The README, the review guide and the defects table describe the
  new pieces.

## v1.20.3 — 2026-10-17 — a busy mirror stops failing the canary

The Kubernetes canary has failed three times in eight days for a reason that
has nothing to do with this repository: the public mirror the base image comes
from refuses anonymous downloads when it is busy. Every one of them passed on a
re-run minutes later.

### Fixed

- **The image build is retried three times**, in both canaries, backing off 15
  seconds then 30. A successful build exits on the first attempt and costs
  nothing — the build itself takes 25 seconds, and the retry only does anything
  once the step has already failed.
- **The failure message now says which kind of failure it was.** A 429 or
  `toomanyrequests` means the mirror is still refusing; anything else is a real
  build failure. Until now the two looked identical from the outside.

### Changed

- **The push skill deletes merged branches on every push.** A squash merge
  leaves the local branch behind, and because its commits never become
  ancestors of `main`, `git branch --merged` cannot tell the work landed —
  so nothing ever removed them. They had reached 44, of which 40 were long
  merged. The new step asks GitHub for each pull request's state instead, and
  never touches a branch whose PR is open or absent.

## v1.20.0 — 2026-10-17 — a database of its own, per pull request

The tests run against PGlite — Postgres compiled into the app — which needs no
database and no secret, and is why they are fast. It is not, however, what the
live site runs on. Every pull request now also gets a real database of its own
to run against, and loses it again when it closes.

Advisory, not a gate. An outage at the database provider should not be able to
block a merge.

### Added

- **A Neon branch per pull request.** A copy-on-write clone of the live
  database, made in seconds, storing only what the tests change.
  `.github/workflows/neon-branch-tests.yml` creates it, runs the database
  suites against it, and deletes it.
- **`scripts/neon-branch.js`** — create, list and delete branches through
  Neon's API, with no new dependency. It refuses to delete the default branch
  (the one the live site uses) and checks the count before creating, because
  the free plan allows ten and an eleventh would fail on a pull request that
  did nothing wrong.
- **`npm run test:db`** — the database-heavy suites on their own. About 4
  seconds against PGlite, about 70 against Neon.
- **Cleanup in three places**, because a branch left behind costs one of ten
  slots: the create step removes any branch of the same name first, the test
  job deletes on `always()`, and a second job deletes again when the pull
  request closes. Every run prints how many branches are in use.

### Fixed

- **Two tests that assumed a fast, local world.** Neither was a difference
  between PGlite and Postgres. The 32-bit GraphQL test makes 22 writes in a
  loop and exceeded the 30-second default once each crossed the network. The
  `bankProfitSign` test compared two price readings taken moments apart —
  a coin's price is a function of time, so they match on a laptop and differ by
  a cent over a network. Both readings are now pinned to the same instant,
  which is an improvement everywhere, not only against Neon.

## v1.19.0 — 2026-10-17 — a room, a lock and a front door

Four steps that take the Kubernetes deployment from the bare minimum to
something closer to a real one: settings of its own, a container that is not
root and cannot write, rules about what may talk to it, and an entrance you
reach by name instead of by port number.

If you only use the website, nothing here changes for you. The app answers on
the same address, and no test needed editing.

### Added

- **`k8s/10-configmap.yaml`** — the settings, reaching the container through
  `envFrom`, so a new one is a single line there. No Secret alongside it:
  nothing in the cluster is sensitive, and a Secret holding nothing teaches the
  wrong habit.
- **`k8s/40-networkpolicy.yaml`** — inbound traffic only on the app's own
  port, outbound only DNS. A compromised app cannot phone home or reach
  anything else in the cluster. Inbound stays open to any source deliberately:
  traffic from outside arrives translated to the node's address and the health
  probes come from the node, so narrowing it would fail the probes.
- **`k8s/50-ingress.yaml` and `ingress-nginx/`** — a front door.
  `http://bank.local:4280` reaches the app by name, alongside the direct
  `127.0.0.1:4273` that every test uses. The controller is ingress-nginx
  v1.15.1, vendored unchanged with its source, version and SHA256 in
  `ingress-nginx/VERSION.md`.
- **Four guard tests** — fourteen in total. They hold the security settings,
  the apply order, the ConfigMap wiring and the Ingress class in place, because
  the scanner that reports on them never fails a build.

### Changed

- **The container is locked down.** `runAsNonRoot` as uid 1000,
  `readOnlyRootFilesystem`, `seccompProfile: RuntimeDefault`, and `USER node`
  in the `Dockerfile`. Safe because the app writes nothing — it serves from
  memory and its database runs in-process — verified by running the image
  directly with `--read-only --user 1000:1000` before any cluster was built.
  Closes four Trivy findings.
- **The manifests are numbered** `00-namespace`, `10-configmap`,
  `20-deployment`, `30-service`, `40-networkpolicy`, `50-ingress`. This fixes
  a real bug: `kubectl apply -f k8s/` applies files alphabetically, so the
  Deployment was being applied before the namespace it declares. It had been
  broken since the namespace landed and was invisible because the canary uses
  the Terraform path, which had explicit ordering.
- **A ConfigMap change now restarts the app.** Kubernetes does not do this by
  itself — it updates the object and leaves running pods on their old values,
  with nothing looking wrong. The pod template carries a checksum of the
  ConfigMap that Terraform rewrites, so a settings change is a real rollout.

### Fixed

- **Two tests that passed only "usually".** The loan rounding check assumed the
  planted bug always shows, when it only shows if the payment has a fraction to
  cut. The loan pricing check assumed two customers' drawn balances always
  differ enough to price differently; it now measures the gap and creates one,
  rather than guessing an amount. Found by running the whole suite three times
  over: one failure in 1159 runs, then none.

## v1.18.0 — 2026-10-17 — a folder, and a room of its own

Two changes to how the app is deployed into Kubernetes, neither of which changes
what the app does or where it answers. Adding a manifest no longer means editing
three files that each named manifests one by one, and the app now runs in a
namespace of its own instead of sharing `default`.

Nothing here is about the website itself. If you only use the site, this release
changes nothing for you.

### Added

- **`k8s/namespace.yaml`** — the app runs in `agents-playground`. It is applied
  by its own Terraform resource that everything else depends on, because
  manifests are otherwise applied in parallel and a Deployment can reach the
  cluster before the namespace it names exists.
- **Two guard tests** in `terraform/tests/guards.tftest.hcl`. One compares what
  Terraform would apply against what is actually in `k8s/`, so going back to
  naming files one by one fails. The other checks the namespace is applied
  first and that every other manifest declares it — a manifest without the line
  fails the test instead of quietly appearing in `default`.

### Changed

- **Every `*.yaml` in `k8s/` is applied, by all three paths.** `terraform/main.tf`
  uses `fileset()` and `for_each`; `.github/workflows/k8s-canary.yml` copies the
  folder to `$RUNNER_TEMP`, rewrites the image tag in the copy and applies the
  folder; `npm run k8s:deploy` is `kubectl apply -f k8s/`. A new manifest needs
  no code change anywhere.
- **Terraform resource addresses changed** to `kubectl_manifest.app["<file>"]`,
  and the `deployment_path` and `service_path` variables became one `k8s_dir`.
  A cluster built before this release will want to recreate its Deployment and
  Service; `terraform state mv` avoids even that.
- **Every command that looks for the app passes the namespace** — `k8s:deploy`,
  `k8s:status`, `k8s:logs`, `scripts/k8s-test.js`, and six `kubectl` calls in
  the canary. A bare `kubectl get pods` now reports nothing, which is correct:
  add `-n agents-playground`, or set it once with
  `kubectl config set-context --current --namespace=agents-playground`.

### Fixed

- **`bankLoanRounding` no longer fails at random.** It asserted that the planted
  rounding bug leaves a loan unpaid, using one fixed amount. The bug cuts the
  fraction of a cent off each payment, so it only shows when there is a
  fraction — and the rate is drawn per customer, so on some draws there was
  nothing to cut and the loan settled normally. It now tries five amount and
  term pairs and asserts on the first that actually moves the payment, and says
  so plainly if none does.

## v1.17.0 — 2026-10-17 — the guards fire before the merge

The Terraform that builds the local Kubernetes cluster has safety rules written
into it — preconditions that refuse a plan when `kind/kind-config.yaml` or
`k8s/deployment.yaml` has drifted from what the code expects. Until now nothing
ran them before a merge: the checks on a pull request read the code without
evaluating a precondition, and the only job that planned or applied anything
ran after the merge. This release moves that forward, and adds tests that prove
the guards still refuse a bad file rather than only that today's files are good.

Nothing here builds a cluster, and nothing here blocks a merge. `Terraform
Validate` stays advisory, and `Pre-Merge Gate` remains the only required check.
The post-merge Kubernetes canary is still what proves the app actually runs in a
cluster.

### Added

- **Seven guard tests**, `terraform/tests/guards.tftest.hcl`, run by
  `terraform test`. Each hands a guard a deliberately broken copy of a manifest
  from `terraform/tests/fixtures/` and requires it to refuse. Both providers are
  mocked, so no cluster, Docker, registry or network is involved — about three
  seconds.
- **`terraform plan` on the pull request.** Preconditions are evaluated at plan
  time, so this is the first thing that makes their messages visible before a
  merge. It needs no cluster and no credentials.
- **A lock-file platform check.** `terraform/.terraform.lock.hcl` must carry
  checksums for `linux_amd64` and `windows_amd64`, because the cluster gets
  built on both. The job re-locks both and fails on a diff, so a lock
  regenerated on one operating system cannot silently drop the other's.
- **`npm run k8s:tf:check`** — formatting, a strict init, validity and the guard
  tests, locally, in seconds, without a cluster. The push gates run it when a
  push touches `terraform/`, `k8s/` or `kind/`.

### Changed

- **`Terraform Validate` now runs for `kind/**`and`k8s/**`, not only
`terraform/**`.** `main.tf` reads those files and holds preconditions about
  what is in them, so without this the one pull request able to break a guard
  was the one that never ran the check.
- **`terraform init` uses `-lockfile=readonly`.** A change to the provider
  constraints in `versions.tf` that did not update the lock file now fails
  there instead of being resolved quietly.
- **The three file paths `main.tf` reads are variables**, defaulting to the same
  files, so a test can point a guard at a broken copy. This is the only change
  to the code that builds the cluster; `npm run k8s:tf:full` was run against it
  — four resources created, 385 tests passed, four destroyed.

## v1.15.0 — 2026-10-10 — the crypto exchange

Playground Bank gains the crypto exchange it was always shaped around: a market
of eight coins, buying and selling with money from a real bank account, a
portfolio, and wallets you can send coin between. The larger change is quieter —
nothing on the site is a fixed table any more. Prices, starting balances, loan
rates and trading fees are all worked out from who the customer is and what they
have done, so two people using the site see different numbers and one person's
numbers move as they use it. Practice mode, the switch that turns every planted
bug on at once, is still to come.

### Added

- **A market that belongs to whoever is looking.** `/app/markets` lists eight
  coins and `/app/markets/:symbol` charts one over an hour, a day, a week or a
  month. A price is a pure function of the customer, the coin and the instant,
  so it moves on its own and no two people share a line. Nothing is stored:
  the chart is the same function asked about the past, so history and the live
  price can never disagree. `GET /api/bank/market`, `GET /api/bank/market/{symbol}`.
- **Buying and selling with bank money.** Ask for a price, the bank holds it for
  fifteen seconds, then confirm: the money leaves your Checking account and the
  coin arrives. The move is written into the same ledger as your transfers and
  bills, so there is one history, not two. `POST /api/bank/trades/quote`,
  `POST /api/bank/trades`.
- **A portfolio.** `/app/portfolio` shows what you hold, what it is worth on
  your own prices right now, what you paid, and whether you are up or down —
  changing while the page is open. `GET /api/bank/portfolio`, `GET /api/bank/trades`.
- **Wallets, with addresses that check out.** Every coin gets you an address like
  `pbx1btc7KZJ3E8B2RTDM`, whose last three characters are a checksum, so a
  mistyped address is refused before any coin moves. Send with a network fee
  charged in the coin itself, or swap one coin straight into another at your own
  two prices. `/app/wallet`, `GET /api/bank/wallet`,
  `POST /api/bank/wallet/send`, `POST /api/bank/wallet/swap`.
- **Five more planted bugs**, off by default and armed per run key like the rest:
  a stale quote still fills, a gain shows as a loss, a quote's total leaves the
  fee out, a mistyped address is accepted and the coin is lost, and a typed
  decimal loses its last unit. `docs/react-surface-defects.md` lists all twenty.

### Changed

- **The loan rate card is gone.** There was a published table — twelve months is
  5.90%, and so on, the same for everybody. Your rate now comes from what the
  bank can see of you: what you hold, how long you have banked here, how your
  earlier loans went, and how big the ask is next to your own money. The quote
  returns the reasons and `/app/bank/loans` shows them in words, so an offer is
  explainable rather than arbitrary. Spend money and your next offer is dearer.
- **New customers no longer all start with the same money.** Opening balances are
  drawn from your own account, roughly $60,000 to $160,000. There is no "the"
  starting balance any more, and tests must not assume one.
- **Trading fees fall as you trade**, from 0.30% to 0.10% on thirty-day volume,
  so a first trade costs the most.
- **The price ticker across the top is live**, from the same data as the markets
  page, so the strip and the rows can never disagree. The hardcoded price list it
  used to read was deleted.
- **GraphQL keeps pace**, with `market`, `coin`, `portfolio`, `trades` and
  `wallet` queries, four new mutations, and `Micros` and `Atoms` scalars — added
  for the same reason `Cents` exists, because GraphQL's `Int` stops at
  2,147,483,647 and one bitcoin is already 67,420,000,000 micro-dollars.

### Fixed

- **An accessibility fault in the app shell, on every page.** The practice-site
  banner sat outside every landmark, so its text belonged to no region and axe's
  `region` rule failed site-wide. It is a labelled region now. The accessibility
  scans were widened from the page content to the whole page so this cannot
  return unnoticed, and a sweep of ten pages is clean.

## v1.0.0 — 2026-08-28 — the remote test runner

Everything below was found by using the deployed runner, not by reading code.

### Known gaps

Stated up front so nobody discovers them the hard way. Checked on every push, so
it describes the runner as it is now.

- **OIDC is not implemented.** Username and password are the only sign-in.
  Deferred deliberately, to be done last.
- **Results are per run, not per test.** A run reports pass or fail. The
  `remote-test-results` artifact carries per-test detail, and reading it needs a
  zero-dependency zip reader that does not exist yet.
- **The runner has no test suite of its own.**
- **Linux visual baselines are absent** for `visual:snapshots` and the two
  visual specs. The screenshots were taken on Windows, so those flows fail on a
  Linux runner over font and antialiasing differences even when nothing is
  broken. The catalog warns about it.
- **No audit log.** Nothing records who ran what beyond GitHub's own run list.

### Added

- **Environment selector.** `pipeline.config.json` gains an `environments`
  section, a new `environment` workflow input, validation in the `plan` job, and
  a dropdown in the runner. Only one environment is configured — `pipeline`,
  meaning the run builds the app from the checked-out commit and serves it
  itself, which is what already happened. Adding a real deployed environment is
  one entry in that file: no workflow edit, no code change. An unknown name
  fails in the `plan` job with the list of valid names, before any shard spends
  time installing a browser.
- **The website under test can now be deployed.** `render.yaml` defines a second
  service for `server.js`, so the runner can target a real host instead of only
  the copy the pipeline builds per run. Optional — skip it and everything still
  works.
- **`CHANGELOG.md`**, this file.

### Changed

- **Flow names are standard QA vocabulary.** `sanity:smoke`, `regression:full`,
  `ui:react`, `contract:api`, and for the generated tiers `app:react-orders` and
  `app:react-orders > tanstack-query`. All 63 flows, all distinct, longest 41
  characters.

  This replaced an earlier attempt at prose names — "Quick check: home, orders,
  product" — which the person using the tool rejected outright. The lesson is
  worth keeping: "smoke", "sanity" and "regression" are the vocabulary of the
  trade, not jargon to be translated away.

  **Flow ids did not change** and are not going to: they appear in
  `.github/workflows/`, in docs, and in people's bookmarks.

- **The flow list is a dense sortable table**, not a grid of cards. Columns are
  FLOW · TESTS · SHARDS · TAGS · RUN. The description and the raw id moved to a
  hover tooltip. Ten flows now occupy a fraction of the space ten cards did.
- **Type scale.** There wasn't one — 74 hard-coded pixel values scattered
  through the stylesheet. There is now, in `rem`, plus `html { font-size: 100% }`
  so the reader's own browser text-size setting finally reaches the page. Body
  went 15 → 18px over two passes.
- **Content width** `--measure` 1180 → 1600px, and a `min-width: 1400px` block
  spends the extra room on larger cards rather than more cramped ones.
- **Run titles carry the requester**: `sanity:smoke · requested by asaf`.
- **`npm run passwd` is now `npm run password`** (`bin/passwd.js` →
  `bin/password.js`). Three documents named the old command, one of them
  printing a copy-pasteable line that failed.

### Fixed

- **The theme toggle did nothing.** `public/app.js` contained the string "theme"
  exactly once: an unused constant. Two buttons in the markup, a complete
  two-theme stylesheet, and no JavaScript connecting them — it had never been
  implemented. Now a three-state cycle (system → light → dark), persisted, both
  buttons in sync, applied before first paint. Every storage access is inside
  `try`/`catch`, because a browser with site data blocked throws on access and
  the page still has to render.
- **Cancel was on the wrong tab.** The Dashboard showed a running run and
  offered no way to stop it; Cancel existed only in History. It now sits on the
  Dashboard's recent-run rows, using the same handler and the same in-flight map,
  so a run stopped from either place reads identically in both.
- **"Started by" said "unknown" after a reload.** The runner dispatches every run
  with one shared token, so GitHub reports the token owner as the actor on every
  row regardless of who pressed the button. The real requester travelled in the
  `reason` input, and GitHub returns dispatch inputs to nobody — so it reached
  the browser only in the response to the runner's own POST, and a reload lost it
  permanently. The requester now travels in the run title, which GitHub does
  return with run metadata.
- **One Users row was 400px tall.** Three action buttons and a paragraph of
  explanation were sharing a table cell about 55px wide. Cause was
  `.col-actions { width: 1% }`, safe only while nothing wrappable is in that cell
  — an assumption that had silently stopped holding. Now 58px.
- **Configuration detail reached only the server log.** `config.js` has always
  split problems into a public half and an operator half carrying the offending
  value. The operator half was logged and never shown, so an administrator
  looking at a broken runner in a browser could see that the invite code was too
  weak but not by how much. It is now returned to administrators, gated on the
  role read from the store on every request rather than from the session cookie,
  so a demoted administrator stops receiving it immediately.
- **A session could outlive its account.** A deleted user's cookie kept working
  for the full 12-hour TTL, and an administrator demoted to `user` stayed an
  administrator until they signed out. `currentUser()` now re-reads the account
  store on every request.
- **A dead "Outcomes" panel** on the Dashboard rendered a heading and nothing
  else. Its renderer had been removed, so it could never show data. Deleted,
  along with seven orphaned CSS rules.
- **The root `Dockerfile` produced a broken app.** It never ran `npm run build`,
  and the React app's Vite output (`public/app`) is gitignored — so every
  `/app/*` route 404s from a clean checkout while the API and server-rendered
  pages look fine. It also pinned the port on the command line, which
  `server.js` reads before `process.env.PORT`, and defaulted `HOST` to
  `127.0.0.1`, unreachable from outside a container.
- **`.env.example` was gitignored** by the `.env.*` rule — the template
  documenting every variable was invisible while real `.env` files stayed
  ignored, correctly.
- **The CLI dispatched to deleted branches.** `trigger-remote.js` defaulted
  `--ref` to the current local branch, so after a merged PR whose branch was
  deleted it produced `HTTP 422: No ref found for`, which reads like a
  permissions problem. It now checks the branch exists on `origin` and falls
  back to `main`.
- **A GitHub lookup failure looked like a test failure.** `/api/dashboard`
  surfaced GitHub's bare `Not Found` to the user. Pipeline problems and test
  failures are now reported separately, which is the point of the runner.

### Decided

Choices that constrain future work. Recorded in
`docs/test-runner-roadmap.md` so they stop being re-argued.

- **No database.** Credentials live in `TR_USERS` as `username:role:scrypt$…`
  entries. Only the hash is stored anywhere. The reason is Render's free plan,
  which has no persistent disk: a file-backed store is wiped on every restart,
  and because the first account created on an empty store becomes an
  administrator, the next visitor would be handed one. The cost is real — adding
  a person means editing an environment variable — and the upgrade path needs no
  code: `src/store.js` already implements the file store and the Dockerfile
  already creates `/app/data`, so attaching a disk turns on persistence and
  self-signup. Rejected: Render's free Postgres (deleted after 30 days) and
  Neon/Supabase (needs the `pg` package, breaking the zero-dependency rule).
- **GitHub's built-in auto-merge**, not an agent, for merging our own PRs.
  **Now live:** the `Repo-Main` branch ruleset requires `Pre-Merge Gate` — which
  itself needs `format` and all four Playwright shards — with zero required
  approvals, and `Allow auto-merge` is on. PRs #23, #24, #25 and #26 merged
  themselves. Arming it stays a per-PR human act, so required checks and human
  approval remain the merge authority and no AI gets push access.
- **OIDC last.** Deferred at the user's request until the rest is done.

### Worth knowing

- **`GITHUB_TOKEN` cannot be granted the `workflows` permission.** It is not in
  the set `permissions:` accepts, so no CI job can ever create or modify a file
  under `.github/workflows/`. This killed a generator that regenerated a `flow`
  dropdown inside the runner workflow; `flow` is free text validated against the
  committed catalog instead. Any future design that needs CI to edit a workflow
  file is impossible, not merely difficult.
- **Read success against a public repository proves nothing about a token.** A
  fine-grained token with no repository access and no permissions returned 200 on
  four read checks purely because the repository is public, and only failed on
  the write it actually needed. Test the operation you care about.
- **Lockout is keyed on (username + address), for 15 minutes.** A correct
  password from an address that is not itself locked always works, so nobody can
  lock anybody else out. The message shown while locked is still the generic
  "Invalid username or password", which is deliberate — an attacker learns
  nothing — but it cost the real account owner about twenty minutes of debugging
  a password that was correct all along. Still open.
